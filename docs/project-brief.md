# Опис проєкту та вимоги

Статус: початкова пропозиція для обговорення. Наведені нижче структура й обсяг ще не є затвердженими рішеннями.

## Що створюємо

Особистий сайт-портфоліо UI/UX дизайнера. Відвідувач має швидко зрозуміти, хто автор, які задачі він вирішує та як із ним зв’язатися.

## Для кого

Попередньо: потенційні роботодавці та замовники. Основну аудиторію потрібно визначити до початку дизайну.

## Запропонована перша версія

Одна головна сторінка з такими розділами:

1. **Знайомство:** ім’я, спеціалізація, короткий опис і перехід до робіт.
2. **Вибрані роботи:** проєкти з обкладинками та короткими поясненнями.
3. **Про себе:** досвід, навички та підхід до роботи.
4. **Контакти:** спосіб зв’язку та потрібні професійні посилання.

Якщо роботи потребують докладних пояснень, можна додати окремі сторінки кейсів. Їхню кількість визначимо після підготовки матеріалів.

## Матеріали для кожної роботи

- Назва та короткий опис проєкту.
- Проблема, яку потрібно було вирішити.
- Роль автора та його внесок.
- Основні етапи й обґрунтування дизайнерських рішень.
- Зображення екранів або прототипу.
- Результат: підтверджені дані або чесний опис висновків без вигаданих показників.

Публікуємо лише матеріали, які автор має право показувати.

## Очікувана поведінка сайту

- Навігація веде до відповідних розділів або сторінок.
- Роботи легко знайти та переглянути.
- Контактне посилання працює.
- Сайт зручно використовувати на телефоні та комп’ютері.
- Тексти й основні дії зрозумілі без додаткових пояснень.

## Поки поза запропонованим обсягом

Блог, особистий кабінет, складна система редагування та контактна форма з надсиланням повідомлень. Їх можна додати за потреби після окремого рішення.

## Відкриті питання

- Яке ім’я та професійне позиціонування показуємо?
- Хто основна аудиторія: роботодавці, клієнти чи обидві групи?
- Якою мовою або мовами буде сайт?
- Скільки робіт готові до публікації та чи потрібні окремі сторінки кейсів?
- Чи є готовий макет у Figma, стиль або приклади бажаного вигляду?
- Які контакти та професійні профілі можна оприлюднити?
- Чи потрібно додати резюме для завантаження?
- Де публікуємо сайт і чи потрібна власна адреса — домен?
- Який бажаний термін запуску?

## Технічне рішення

Ще не обране. Для простої першої версії можна розглянути HTML і CSS, а JavaScript додавати для потрібної взаємодії. Остаточний вибір залежить від погодженої структури та функцій.
